Here is the breakdown of the formulas I tweaked from the starting point for the compute_urgency() methods and why I changed them:

1. BatteryAgent Formula Change
- Starting point suggested: Linear curve (urgency = 1.0 - (SoC / 100.0))
- What I changed it to: Non-linear squared curve (urgency = ((100.0 - SoC) / 100.0) ** 2)
- Why: A linear curve means a battery at 50% SoC demands a 0.5 urgency score. That feels way too aggressive since half-full is still pretty safe. Squaring the value keeps the urgency super chill while the battery is relatively healthy, but makes it spike hard once it drops to critical levels.

2. ApplianceAgent Time Window Logic
- To calculate the urgency ramp-up for deferrable appliances, I assumed a standard 4-hour (240 min) maximum operating window. The urgency approaches 1.0 as the time left in that 240-minute window shrinks to zero.
- I also had to add explicit None checks using the _is_missing() function to prevent Pylance/linter crashes when casting those time variables to floats.

3. ApplianceAgent Window-Closed Case (Open Question)
- For the edge case where the appliance window is completely closed or missed, I explicitly set it to return 0.0.
- Why: If it missed its window, it shouldn't turn on at all, meaning it demands zero power right now.
- Open Question: Should we be logging these missed windows instead of just silently returning 0.0?
